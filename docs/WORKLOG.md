## Правила ведения

- Добавлять записи в конец; не переписывать историю задним числом.
- Различать **подтверждено**, **исторически сообщалось**, **предположение** и **неизвестно/конфликт**.
- Указывать ветку, SHA и доказательства только при фактической доступности.
- Записывать реально выполненные проверки; просмотр исходника не означает runtime-проверку, сборка не означает проверку на устройстве.
- Сохранять неудачные попытки и отрицательный опыт, если они помогают избежать повторения.
- После существенного этапа согласованно обновлять журнал, [текущее состояние](PROJECT_STATE.md) и [handoff](HANDOFF.md).
- Не хранить секреты, токены, cookies или личные данные.

## 2026-10-10 — CARD111 scanner regression patch (remote-source validation only)

- **Задача / исходное состояние:** пользователь сообщил, что сканер нагружает/подвешивает телефон, фото из галереи не приводит к добавлению кода, а перемещение изображения под рамкой исчезло.
- **Исходная точка:** repo `alexbotleh-oss/CARD`, branch `gh-pages-CARD111-ui`, исходный HEAD `cb0359261d0646112b8523ec3a33d691f71a1b7f`, исходный blob `index.html` `f5e616abc2df68ab703bdb4dad3a972d907d197c`; `sw.js` cache v50. Локальная рабочая копия/status недоступны; работа выполнена через удалённый GitHub API.
- **Что изменено:** `index.html` — отдельный одноразовый путь завершения для фото; уменьшенная копия до 1600 px для первичного распознавания; перемещение изображения одним пальцем при увеличении; учёт трансформации при обрезке и ограничение выходной области до 1800 px; камера 1280×720/15 fps и интервал обнаружения 160 ms; очистка камеры при закрытии окна и защита от запоздавшего результата после остановки. `sw.js` — cache v50 → v51.
- **Коммиты:** `e9932cda419013b2ffe284c30901c04780c8de77`, `2bd99024fd342330d8dbf81cd207885da4357cd2`, `565addebcaa3390096fa7a0a2f103551734bad91`.
- **Проверки:** после изменения `index.html` повторно прочитан через GitHub API; оба inline JS-блока проходят синтаксическую проверку; наличие ключевых условий подтверждено статическими проверками; `sw.js` повторно прочитан, cache v51 подтверждён. E2 — синтаксис/статические условия.
- **Ошибки / ограничения:** реальный Android/runtime-тест не выполнялся; зависание не воспроизводилось инструментально. Точная причина нагрузки не доказана, но цикл камеры был не ограничен по частоте и запрашивал 1920×1080. Установлено расхождение: `main` содержит старый индекс (blob `531be277f985eddc81d85a362b93fbcd21ec10ef`, cache v7), а `gh-pages-CARD111-ui` — исправленный индекс/cache v51. Источник опубликованной страницы не подтверждён.
- **Решение / защита данных:** не очищать storage и не менять данные карт. Исходная точка Git — commit `cb0359261d0646112b8523ec3a33d691f71a1b7f` остаётся доступной для отката.
- **Дополнительный focused patch:** commit `cadee049c62afc2d42e3ed297e41bb404b819929` (`index.html`) закрывает гонку позднего завершения `decodeFromVideoElement`: при завершении подключения после остановки новый `controls` сразу останавливается и не сохраняется; запоздалый callback камеры игнорируется. Одновременно исправлен `serviceWorker.register` с `sw.js?v=50` на `sw.js?v=51`, согласовано с `card-pwa-v51`.
- **Повторная проверка после последнего коммита:** `index.html` blob `dcccba9121dd9af70858634557ce014a647e7f00`; `sw.js` blob `f088d3901769ea2f01b58ab789ff4563d4a48aac`, cache `card-pwa-v51`; оба inline JS-блока проходят синтаксическую проверку. Статические проверки подтвердили интервал `nativeLoop`, снижение разрешения камеры, guard для позднего ZXing, bypass двух hits для фото, pan и согласованную версию service worker. `requestAnimationFrame(nativeLoop)` не найден — это ожидаемо после перехода на `setTimeout`, а не ошибка.
- **Следующий шаг:** установить фактический источник GitHub Pages и проверить опубликованный HTML; затем выполнить ручную проверку на Android. До этого исправление не считать проверенным в целевой среде.


## 2026-10-10 — CARD111: галерея, чёрный экран при выборе QR-скриншота
- Симптом от пользователя: обычный скриншот списка карт открывается, а скриншот лояльности с крупным QR-кодом после выбора из галереи приводит к чёрному экрану.
- Гипотеза по коду: после выбора изображения видеопоток останавливался, но интерфейс предпросмотра появлялся только после завершения попыток BarcodeDetector/ZXing. На телефоне с долгим распознаванием область могла оставаться чёрной; первопричина на устройстве пока не подтверждена.

Если код распознаётся, штатный путь результата по-прежнему закрывает окно; если нет — фото уже доступно для перемещения/масштабирования и ручного распознавания области.
- Коммиты: index preview `c128b675ea36fe2e7c025289dd998d9e2f05e104`; SW cache v52 `75ed76db397708bf9cbc11226cf025bab8483920`; регистрация `sw.js?v=52` `7588036595c336a3501a64b2a9509cf1ec6f9fdc`.
- Проверки: оба inline JS-блока прошли синтаксический разбор; регистрация SW и cache v52 согласованы. Это статическая проверка, не проверка камеры/галереи на Android. Требуется проверить опубликованную страницу и выбрать QR-скриншот.
