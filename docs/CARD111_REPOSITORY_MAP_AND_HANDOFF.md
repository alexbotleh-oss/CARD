**Статус:** восстановление структуры и проверка источника публикации в процессе. Не считать сайт обновлённым, пока это не проверено по фактическому ответу Pages.

## Каноническая схема веток

| Ветка | Роль | Правило |
|---|---|---|
| `main` | Единственная утверждённая версия | Только изменения, принятые пользователем и прошедшие предусмотренные проверки |
| `develop` | Единственная постоянная рабочая ветка | Новые исправления и интерфейсная работа; сюда интегрируются отдельные проверенные изменения |
| `backup/stable` | Резервная контрольная точка | Снимок утверждённого `main`; обновлять после принятия стабильной версии |

Временная схема создана, но до завершения аудита не удалять старые ветки и не менять источник GitHub Pages наугад.

## Правила дальнейшей работы

1. Сверить фактическую конфигурацию GitHub Pages и URL, не меняя её до доказательства.
2. Для каждого расхождения зафиксировать ветку, commit SHA, файл, смысл, тесты и решение.
3. Работать только в `develop`; один логически ограниченный change за раз.
4. Перед изменением сохранить SHA и контрольную точку; после — синтаксическая проверка, reverse-diff и регрессия затронутых функций.
5. Не переносить код в `main` без явного утверждения пользователя.
6. После утверждения обновлять `main`, затем `backup/stable`.
7. Старые ветки удалять только после сравнения их уникальных коммитов/файлов и сохранения нужных точек возврата.
8. Различать статическую проверку исходника (E2) и фактическую проверку в браузере/на Android (E3).
