## 5. Исторические опорные сведения

В предыдущей истории проекта как рабочая точка web UI упоминались `candidate/CARD111-ui-2xN-20261006` и коммит `a1085aa7799998b80946808247775c9b4f5f0df3`. Это историческая запись, а не автоматически выбранная база для новой правки. Перед кодом найди текущий подтверждённый рабочий путь (WP) и сверь его с CORE.

Журнал инцидентов содержит:
- APK Flet API regression — FIX3 прошёл `py_compile`, но указан как UNVERIFIED без Android E3.
- Web scanner syntax regression — исправление прошло E2 parse по записи, но live/device E3 не подтверждён в этой записи.

Не считай ни APK, ни web-релиз готовым без проверки требуемого уровня в целевой среде.

## 7. Следующее конкретное действие

**Перед следующей задачей разработки:**
1. Получить свежий HEAD `main` и проверить новые документы.
2. Сверить задачу пользователя с WORKLOG, PROJECT_STATE и журналом инцидентов.
3. Если задача касается кода — определить WP/снимок и текущие проверяемые артефакты, не опираясь только на старую память.
4. Выполнить один логический шаг по активному CORE, провести применимые проверки и после этого обновить WORKLOG, PROJECT_STATE (если изменился статус) и HANDOFF.

**Критерий завершения первого шага:** актуальная ветка/SHA и источники определены; известно, что реально подтверждено и что остаётся неизвестным; выбран ровно один следующий шаг.
