# CARD — журнал ошибок и контрольных состояний

## 2026-10-05 — INCIDENT-CARD-001 — APK Flet API regression

**Наблюдение:** после сканирования APK падал с:
`AttributeError: module 'flet' has no attribute 'ElevatedButton'`.

**Корень:** контрольный FIX1 использовал Flet 1.0 API `ft.Button`, но при подготовке FIX2_STORAGE в `main.py` были возвращены два старых вызова `ft.ElevatedButton`. Это произошло вне заявленного storage-change и не было поймано reverse-diff до выдачи результата.

**Доказательство:** сравнение FIX1 → FIX2 показывает ровно два возврата `ElevatedButton`; сравнение FIX2 → FIX3 показывает замену этих двух вызовов на `ft.Button(content=...)`.

**Контроль из соседнего проекта B77:** INCIDENT-049 — Flet API mismatch; Flet 1.0 требует API-совместимый аудит. Также INCIDENT-055 — запрет каскада непроверенных изменений после последнего рабочего состояния.

**Корректирующий контроль:**
- Flet API compatibility audit перед каждым UI change.
- После каждого change — E2/reverse-diff до следующего change.
- Не брать новый файл/реализацию вместо WP только потому, что он новее.
- Не выдавать APK как проверенный без реального Android E3.

## 2026-10-05 — INCIDENT-CARD-002 — Web scanner syntax regression

**Наблюдение:** текущий `index.html` не проходил JavaScript parse: script3 завершался `SyntaxError: missing ) after argument list`.

**Корень:** scanner FIX добавил лишнее экранирование кавычек в строке кнопки галереи: `\\\\'scanFile\\\\'` вместо `\\'scanFile\\'` внутри JS-строки. Это делало весь основной script неисполняемым.

**Контроль:** E2 parse текущего `index.html` после исправления — все 4 script-блока PASS. Reverse-diff — ровно 1 строка. Service-worker cache поднят v6 → v7, чтобы устройство не удерживало дефектный cached index.

**Статус:** Web FIX синтаксически подтверждён E2; live/device E3 ещё отсутствует. Не считать новым WP.


## 2026-10-10 — INCIDENT-CARD-003 — Gallery scan result dropped; image pan and camera-load issues

**Симптом пользователя:** сканер зависает/сильно нагружает телефон; фото из галереи не завершает добавление кода; прежнее перемещение изображения карточки под рамкой отсутствует.

**Подтверждено проверкой исходника ветки `gh-pages-CARD111-ui`:**
- `finish()` требовал два одинаковых результата для камеры, но путь распознавания статичного изображения вызывал его только один раз. Фото могло распознаться, однако результат отбрасывался.
- В cropper были обработчики масштабирования двумя пальцами, но не было перемещения изображения одним пальцем.
- Камера запрашивала 1920×1080, а цикл `BarcodeDetector.detect()` не имел явного ограничения частоты.
- Закрытие модального окна не гарантировало остановку камеры.

**Исправление сохранено в ветке `gh-pages-CARD111-ui`:**
- commit `e9932cda419013b2ffe284c30901c04780c8de77` — галерея, панорамирование изображения, уменьшенная обработка фото, ограничение нагрузки камеры и освобождение ресурсов;
- commit `2bd99024fd342330d8dbf81cd207885da4357cd2` — cache-bump service worker v50 → v51;
- commit `565addebcaa3390096fa7a0a2f103551734bad91` — не обрабатывать результат камеры, если сканер уже остановлен.

**Проверки:** актуальный `index.html` повторно прочитан через GitHub API; оба inline JavaScript-блока прошли синтаксическую проверку через `new Function`; наличие ключевых исправлений подтверждено чтением исходника. Это E2 для синтаксиса/статических условий, не runtime, не проверка на Android и не подтверждение публикации.

**Ограничения/неизвестное:** зависание устройства не воспроизведено независимо; снижение нагрузки — профилактическое исправление, а не доказанный первопричинный диагноз. Настройка GitHub Pages не подтверждена. `main` всё ещё содержит другой старый `index.html` (blob `531be277f985eddc81d85a362b93fbcd21ec10ef`) и `sw.js` с cache v7; ветка `gh-pages-CARD111-ui` содержит исправленный код и cache v51. Не утверждать, что опубликованный URL уже обслуживает эту ветку.

**Следующий шаг:** подтвердить источник GitHub Pages/раздаваемую версию, затем проверить выбор изображения, распознавание без камеры, панорамирование/масштабирование/обрезку, остановку камеры при закрытии и возврат к кошельку на Android. До проверки на устройстве статус остаётся UNVERIFIED.
